# Proposal for Codex issue #34656

Preserve a verified Claude Code compaction checkpoint when importing a **new** session. Keep the previously imported transcript visible and bound the reconstructed model history before first continuation.

## Reproduction

The seven-record [synthetic Claude JSONL](claude-minimal.jsonl) contains a superseded prefix, a one-message preserved segment, a compact boundary, an intermediate attachment, a summary, and a logical tail. It demonstrates the semantic defect without a large request, account or model call.

From this repository, use a local checkout of public Codex containing the baseline commit, with Git and the Rust toolchain installed.

```sh
CODEX_CHECKOUT=/fictional/source/openai-codex
./upstream/run-repro.sh "$CODEX_CHECKOUT"
```

The runner uses a disposable copy of [baseline `0184dfa6a48f0110dd9c6835522492908e5abcf3`](https://github.com/openai/codex/commit/0184dfa6a48f0110dd9c6835522492908e5abcf3). Its Rust test calls the real Claude importer and asserts that the superseded text, preserved message, summary and tail are emitted as ordinary model messages, with no `CompactedItem`. The fixture is intentionally small. The reproduced behavior can lead to an input-item limit or a token-window limit in a large session.

The same file has a proposed contract test for an importer that emits a Legacy checkpoint in its exported rollout. To run it against a trusted, committed local implementation, pass `--expect-fix`. It is expected to fail on the unmodified baseline. If the boundary is materialized by App Server at persistence time, place the assertions at that integration boundary. [Regression source](claude_compaction_regression.rs)

## Root cause and minimum fix

1. **Parse within the Claude importer.** The Claude reader filters to user/assistant messages and drops the system boundary. A text summary can survive as ordinary user text, or be filtered according to its other flags. Add a Claude-specific checkpoint representation in `records_cla.rs` and the parsed session model. Associate a main-line boundary with its unique usable summary through parent links, including intermediate attachments. Validate declared preserved endpoints and their anchor. Resolve the effective logical tail and use the latest verified effective boundary. Reject ambiguous candidates and keep the current import behavior for those inputs. Keep Cursor and the import ledger's byte digest semantics unchanged. [Pinned Claude parser](https://github.com/openai/codex/blob/0184dfa6a48f0110dd9c6835522492908e5abcf3/codex-rs/external-agent-migration/src/sessions/records_cla.rs#L106-L229)
2. **Separate transcript from model replay.** In `export.rs`, retain the original UI transcript and build a checkpoint intent from the source summary and verified preserved items. Keep the summary at user-context authority and reserve ordinary user labeling for actual prompts. Persist the checkpoint where the reconstruction sees it before the logical suffix, or include the logical suffix in the replacement at the completed import. Ensure each retained or tail item enters the effective context once. Use the current `codex_history::CompactedItem` and replacement item envelopes. If metadata requires trusted thread state, allocate it in App Server import persistence, where the initial context-window and importer state are available. Avoid filling fields merely to satisfy a presence gate. [Pinned exporter](https://github.com/openai/codex/blob/0184dfa6a48f0110dd9c6835522492908e5abcf3/codex-rs/external-agent-migration/src/sessions/export.rs#L39-L210) · [Pinned import persistence](https://github.com/openai/codex/blob/0184dfa6a48f0110dd9c6835522492908e5abcf3/codex-rs/app-server/src/external_agent_migration/session_importer.rs#L458-L511)
3. **Respect recovery mode.** The reviewed import writer emits Legacy history. Core bounded Legacy selection requires replacement history, a window number and valid resume metadata. Populate metadata from the real initialized import state. Never infer provider compatibility identifiers, tool permissions or remote usage from a Claude transcript. Paginated bounded selection needs replacement history and a window number and can operate without Legacy resume metadata. Keep that path compatible via serialization and replay tests. Do not change the import mode as part of this fix. An old-format checkpoint may still replace history during full replay, a separate behavior from bounded resume. [Selection and replay](https://github.com/openai/codex/blob/0184dfa6a48f0110dd9c6835522492908e5abcf3/codex-rs/core/src/session/rollout_reconstruction.rs#L62-L93) · [Resume metadata](https://github.com/openai/codex/blob/0184dfa6a48f0110dd9c6835522492908e5abcf3/codex-rs/history/src/compaction_resume_metadata.rs#L15-L58) · [Store reader](https://github.com/openai/codex/blob/0184dfa6a48f0110dd9c6835522492908e5abcf3/codex-rs/thread-store/src/local/model_context.rs#L35-L94)
4. **Rebase the imported estimate.** The exporter estimates the imported text and persists a `TokenCount` used on startup. Compute an import estimate from the actual post-checkpoint model history. Place the estimate where the runtime expects its covered prefix, or exclude separately estimated suffix tokens to avoid counting twice. An import estimate has no billable counters. Preservation of real later provider usage is a separate migration problem. [Exporter token event](https://github.com/openai/codex/blob/0184dfa6a48f0110dd9c6835522492908e5abcf3/codex-rs/external-agent-migration/src/sessions/export.rs#L193-L211) · [Startup usage selection](https://github.com/openai/codex/blob/0184dfa6a48f0110dd9c6835522492908e5abcf3/codex-rs/core/src/session/mod.rs#L2119-L2136)

Start with new Claude imports. Leave the existing append and repair flows outside this patch. The append path checks an exact transcript prefix and rejects compaction records. Keep it fail-closed for affected histories until it has a separate compatibility design. This proposal does not need the Session Doctor CLI, recovery registry, candidate files or fork RPC. [Append validation](https://github.com/openai/codex/blob/0184dfa6a48f0110dd9c6835522492908e5abcf3/codex-rs/external-agent-migration/src/sessions/append.rs#L167-L194)

## Comparison and completion criteria

The [reference draft by mh0pe](https://github.com/mh0pe/codex/pull/1/files) introduces a summary message type and emits a summary-only replacement while retaining older transcript records and rebasing its estimate. Its source layout predates the Claude/Cursor parser split. It uses an older checkpoint constructor with no window number or Legacy resume metadata. The proposed change keeps the transcript preservation and estimate ideas while validating actual source pairing, explicit preserved segments, logical tails and current recovery metadata.

Extend the native tests to round-trip the produced rollout through the canonical decoder and actual reconstruction for Legacy and Paginated. Assert that old transcript events stay visible, effective model items contain the expected ordered summary/preserved/tail sequence, subsequent Codex turns stay intact, and the startup estimate covers the intended prefix exactly once. Include multiple checkpoints, malformed/ambiguous input, no checkpoint, and unknown retained state. The supplied importer regression demonstrates the baseline defect. The separate [native replay harness](../session_doctor_native/reconstruction_test.rs) shows the reconstruction assertions on an isolated synthetic candidate.
